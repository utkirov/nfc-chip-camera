# Camera Check — NFC-паспорт камеры

В каждую проданную камеру встраивается NFC-чип. Покупатель прикладывает телефон, открывается
сайт проверки: **«Оригинал»**, фото и данные именно этой камеры, гарантия и контакты магазина.
Все данные вы заводите и модерируете в админ-панели.

> Сейчас это **прототип на мок-данных**: сервера нет, «база» хранится в localStorage браузера.
> Админка и сайт проверки открываются с одного адреса и видят одни и те же данные,
> поэтому изменения в админке сразу видны на странице проверки.

## Два сайта

| Путь | Для кого | Что внутри |
|---|---|---|
| `verify/` | покупатели | Результат проверки (6 состояний), галерея фото, паспорт камеры, комплектация, гарантия, контакты |
| `admin/` | вы | Вход, обзор и тревоги, список камер с поиском и фильтрами, карточка камеры (фото, данные, продажа), мастер привязки чипа, журнал проверок, настройки |
| `index.html` | демо | Ссылки на оба сайта и симулятор касаний |

Вход в админку (демо): `admin` / `camcheck`.

## Как работает проверка на простом чипе (без DNA)

Используем дешёвые **NTAG213/215/216**, но включаем в них встроенную функцию **UID + counter mirror**.

1. В чип записывается ссылка `https://cameracheck.uz/?c=CC-0001&m=`
2. Включается mirror: при **каждом** чтении чип сам дописывает в конец ссылки свой заводской UID
   и счётчик касаний: `…&m=04A1B2C3D4E5F6x00000F`
3. Чип закрывается паролем, чтобы ссылку нельзя было стереть или подменить.

Сервер при открытии ссылки проверяет:

| Проверка | Если не прошла → покупатель видит |
|---|---|
| Камера есть в базе и не черновик | **Метка не зарегистрирована** |
| Камера не заблокирована | **Камера заблокирована** (кража/утеря) |
| В ссылке есть `m=UIDxСЧЁТЧИК` | **Подлинность не проверена** (ссылку открыли вручную) |
| UID совпадает с привязанным к камере | **Метка не прошла проверку**: ссылку переписали на другой чип |
| Счётчик больше последнего | **Приложите телефон ещё раз**: открыли старую сохранённую ссылку |
| Всё прошло | ✅ **Оригинал**, новый счётчик запоминается |

**Что это даёт:** обычное копирование метки приложением (NFC Tools и т. п.) не проходит,
потому что у новой метки другой заводской UID. Скриншот или пересланная ссылка тоже не проходят:
счётчик уже использован.

**Честное ограничение:** против специальных «магических» клонов, у которых можно подделать UID,
простой чип не защищает. Для этого нужен NTAG 424 DNA с криптоподписью. Логика сайта уже
построена так, что на DNA-чипы потом меняется только функция проверки
(`shared/js/verify-engine.js`), а сайты остаются прежними.

Дополнительно помогает то, что чип спрятан внутри корпуса, а в админке виден журнал всех
проверок: попытки подделки и сканы заблокированных камер попадают в «Тревоги».

## Привязка чипа (админка → камера → «Привязать чип»)

1. **NXP TagWriter** (бесплатно, Android/iOS): записать ссылку, включить *UID mirror* и
   *Counter mirror*, поставить пароль.
2. Считать UID: в Chrome на Android прямо из админки (Web NFC), иначе ввести вручную
   (TagWriter его показывает).
3. Сохранить. Первое касание покажет «Оригинал».

## Структура

```
index.html                 демо-страница + симулятор касаний
verify/index.html, app.js  сайт проверки
admin/index.html, app.js   админ-панель
shared/
  js/store.js              мок-база (localStorage) и справочники статусов
  js/verify-engine.js      логика проверки — в продакшене переезжает на сервер
  css/base.css             общие стили
  css/tailwind.css         собранный Tailwind (коммитится)
  img/cameras/*.webp       фото камер без фона
```

## Запуск

```bash
npm install
npm run build:css   # после изменения классов Tailwind
npm run serve       # http://localhost:8080
```

## Фото

Демо-фото камер без фона взяты с pngimg.com (лицензия CC BY-NC 4.0, только некоммерческое
использование). Для реального запуска замените их своими фото аппаратов: админка принимает
PNG без фона и сжимает в WebP.
